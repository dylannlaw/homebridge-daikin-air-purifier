# Adopt the docs-first workflow

## Summary

Changes now follow a docs-first process: read the history, plan larger changes, build, verify, update the docs, record a change note, open a PR. It is written down in plain files so any contributor or coding agent can follow it.

## Why

This repository had no working agreement, `docs/` folder or PR checklist. Decisions such as why control goes through the cloud, or why login failures stop retries, lived only in commit messages and the README.

## Design

- `AGENTS.md` is the single source of rules, in the cross-tool format that most coding agents read. `CLAUDE.md` is one line pointing to it, for tools that look for that file name.
- `docs/` holds the index, the workflow, and templates for plans and change notes.
- The structure follows the docs-first workflow used in my other repositories, trimmed to what a public repository needs. Left out on purpose, because this repository is public and contributors may use other tools:
  - tool-specific settings (no `.claude/`, no hooks, no plugin or model-routing setup);
  - a machine-readable `standard.json` and a CI drift check, which would depend on a repository that may be private. The verify command and the sensitive areas are written in `AGENTS.md` and `SECURITY.md`.
- `CHANGELOG.md` stays generated by standard-version, so reasoning goes in `docs/changes/`.
- The default branch is `master`.
- `docs`, `AGENTS.md`, `CLAUDE.md` and `SECURITY.md` are in `.npmignore` so they aren't published.
- `dependabot.yml` covers GitHub Actions and npm.
- Considered only moving the README into `docs/`: rejected, because the README is what Homebridge users read.

## Files

- `AGENTS.md`, `CLAUDE.md`, `SECURITY.md`: the working agreement and security policy.
- `docs/`: index, workflow, plan and change-note templates, and this note.
- `.github/pull_request_template.md`, `CODEOWNERS`, `dependabot.yml`: PR checklist, review owner and dependency updates.
- `.npmignore`: keeps the new files out of the package.
