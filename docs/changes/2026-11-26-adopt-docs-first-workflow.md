# Adopt the docs-first workflow

## Summary

The repository now follows the shared standard in [dylannlaw/agent-skills](https://github.com/dylannlaw/agent-skills) (`engineering-workflow`): read the history, triage, plan, build, verify, document, record, PR.

## Why

The other repositories already follow it; this one had no `AGENTS.md`, `docs/` folder or PR checklist. Decisions such as why control goes through the cloud, or why login failures stop retries, lived only in commit messages and the README.

## Design

Files were taken from the pack's `templates/` and filled in for this repository. Differences from the templates:

- The default branch is `master`, so the CI job and `AGENTS.md` say `master`.
- `standard.json` uses the existing `npm run lint && npm test` as the verify command, and `eslint --fix` as the format hook. `sensitivePaths` are the login/API client, the config entry point and schema, and the release workflow.
- `CHANGELOG.md` stays generated by standard-version, so it is not a place to hand-write notes; change notes in `docs/changes/` hold the reasoning.
- `docs`, `AGENTS.md`, `CLAUDE.md`, `SECURITY.md` and `standard.json` are in `.npmignore` so they aren't published.
- `.claude/settings.json` (the pack's recommended file) is left out: this is a public repository and contributors may use other tools or setups. The workflow lives in plain files (`AGENTS.md`, `docs/`) that any agent or person can follow.
- The npm ecosystem was added to `dependabot.yml`.
- Considered only reorganising the README into `docs/`: rejected, because the README is what Homebridge users read and the standard keeps it as the description of "now".

## Files

- `AGENTS.md`, `CLAUDE.md`, `standard.json`, `SECURITY.md`: the working agreement and its settings.
- `docs/`: index, workflow, plan and change-note templates, and this note.
- `.github/pull_request_template.md`, `CODEOWNERS`, `dependabot.yml`: PR checklist, review owner and dependency updates.
- `.npmignore`: keeps the new files out of the package.

## Docs updated

`README.md` needs no change: users see no difference.

- Backfill plans or notes for the login and cloud-control decisions if they come up again.
